# BiliFrame

BiliFrame 是面向桌面端哔哩哔哩 HTML5 播放器的 Tampermonkey 用户脚本，为视频观看增加逐帧控制、当前帧截图和原始封面查看功能。

项目名为 **BiliFrame**，仓库名为 `biliframe`，当前版本为 `0.1.1`。项目目前尚未发布到 GitHub；本文中的本地安装方式适用于开发和测试阶段。

## 功能

- 按浏览器实际解码时间估算帧间隔，逐帧后退或前进；无法取得采样时使用 30 FPS 作为安全回退。
- 将当前视频画面预览并保存为带标题和 BV/剧集标识的 PNG。
- 读取原始封面，预览、打开原图、复制原图地址或下载原图。
- 适配播放器重建、单页导航、宽屏、网页全屏和全屏场景；不满足播放器条件时保持页面不变。
- 控件沿用哔哩哔哩播放器的按钮外观，并提供可访问名称、提示文字和键盘激活。

逐帧操作是浏览器时间线上的近似定位，并非对编码器进行逆向解码；可变帧率视频的步进精度可能不同于恒定帧率视频。

## 支持的路由

脚本匹配以下桌面路由，并且仅在检测到可用视频和播放器控制栏后挂载：

- `https://www.bilibili.com/video/*`
- `https://www.bilibili.com/bangumi/play/*`
- `https://www.bilibili.com/medialist/play/*`
- `https://www.bilibili.com/list/watchlater*`
- `https://www.bilibili.com/festival/*`

移动端页面、直播、嵌入式第三方播放器和离线客户端不在支持范围内。

## 安装与更新

### 本地安装

1. 安装并打开兼容 Tampermonkey 的用户脚本管理器。
2. 在本项目中找到 [`src/biliframe.user.js`](src/biliframe.user.js)，将文件拖入管理器，或在管理器中使用“从文件安装”。
3. 检查脚本名称、匹配范围和权限后确认安装。
4. 打开或刷新支持的哔哩哔哩视频页面。

脚本文件是可直接安装的单文件 userscript，不需要先构建，也不需要安装运行时依赖。

### 更新

开发阶段重新下载或替换 `src/biliframe.user.js` 后，在脚本管理器中重新导入；若管理器提示同名脚本，选择更新现有脚本。未来若通过 GitHub 发布，可使用发布方提供的 raw 文件地址更新，但当前项目尚未发布 GitHub，因此不要使用未提供的在线地址。

## 按钮与快捷键

播放器原生播放/暂停按钮后会出现四个按钮，顺序固定为：

| 按钮 | 操作 |
| --- | --- |
| 上一帧 | 暂停视频并向前定位一个估算帧间隔 |
| 下一帧 | 暂停视频并向后定位一个估算帧间隔 |
| 截取当前画面 | 直接单击后按视频原始尺寸截取，并显示可查看、下载的 PNG 预览 |
| 查看视频封面 | 直接单击后显示原始封面，并提供下载、打开原图和复制地址操作 |

快捷键只用于逐帧控制：`Alt+,`（上一帧）和 `Alt+.`（下一帧）。截图与封面按钮不需要 `Alt`，直接单击即可。焦点在输入框、文本域、选择框、按钮、链接或可编辑元素中，或同时按下其他修饰键时，快捷键不会接管页面操作。按钮也可聚焦后使用 `Enter` 或空格键激活。

单击截图或封面按钮只生成并显示预览，不会立即下载或打开新页面。预览窗口中的“下载截图”“复制当前时间链接”“下载原图”“打开原图”和“复制图片地址”都必须由用户再次主动点击触发。

## 权限与隐私

脚本声明的权限及用途如下：

- `GM_download`：仅在预览窗口点击“下载截图”或“下载原图”后请求保存图片；远程下载域限制为 `hdslb.com` 及其子域名。
- `GM_openInTab`：仅在点击“打开原图”后打开封面。
- `GM_setClipboard`：仅在点击复制操作后写入图片地址。

BiliFrame 不包含统计、遥测、Cookie、账号数据或后台网络请求，不读取私有 Bilibili API、凭据或页面全局私密数据。除用户主动触发的封面打开/下载等行为外，不主动联网。脚本本身无运行时依赖，项目开发检查仅使用 Node.js 内置测试运行器。

## 限制

- 不下载、合并或转码视频/音频流，不绕过 VIP、DRM 或任何访问控制。
- 不修改哔哩哔哩原有快捷键、播放设置或账号状态。
- 浏览器未提供统一的反向解码接口，逐帧后退是基于媒体时间线的定位近似。
- 跨域或受保护的视频画布可能无法导出截图；脚本会显示错误而不是静默失败。
- 没有可用原始封面时，封面按钮无法完成预览；下载器不支持时可改用浏览器打开原图后另存。
- 不自动安装 Tampermonkey 或本脚本，也不负责创建或推送 GitHub 仓库。

## 故障排查

### 页面没有出现按钮

确认脚本已启用、页面属于支持路由，并完整刷新视频页。若播放器仍在加载，等待视频控件出现后再检查；直播、移动端或第三方播放器不会挂载。若仍无按钮，请先查看脚本管理器控制台中的错误信息。

### 封面不可用或下载失败

确认页面已加载视频信息且存在封面。可以在封面窗口选择“打开原图”，再由浏览器保存；若管理器拒绝下载，请检查其跨域下载权限以及网络是否能访问 `hdslb.com`。

### 截图失败

视频必须已经加载并显示有效画面。跨域限制、受保护媒体或浏览器画布安全策略会阻止 PNG 导出；刷新页面并等待播放画面出现仍无效时，属于浏览器安全限制，BiliFrame 不会绕过它。

截图成功后会先显示预览；如果预览已经出现但文件尚未保存，请继续点击预览下方的“下载截图”。

### 逐帧位置不够准确

逐帧间隔来自浏览器已解码帧的采样，刚打开视频、发生缓冲或视频为可变帧率时可能暂时回退或产生近似结果。暂停后连续操作，等待状态提示显示稳定 FPS，可获得更一致的定位。
